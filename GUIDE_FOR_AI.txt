LoezF_Bot — Telegram-бот для управления приёмом новых участников (нью)
во флуд-чаты и ролевые сообщества.

⛔ ВАЖНО: Проект полностью завершён и стабильно работает.

🔹 ОСНОВНАЯ ЦЕЛЬ:
Автоматизация приёма новых участников (нью) во флуд-чаты.

🔹 АУДИТОРИЯ:
Участники фандомов и ролевых сообществ.

🔹 КЛЮЧЕВЫЕ ФУНКЦИИ:

📌 ОПИСАНИЕ:
Бот использует прокси для подключения к Telegram API.
С 24.09.2026 используется платный прокси Webshare
(надёжнее, чем публичные). Приоритетный прокси задаётся в .env.

📌 ПУТИ К ПРОКСИ:

PROD: PROXY_DIR=C:\Users\olika\PyCharmMiscProject\proxy_manadger
TEST: PROXY_DIR=C:\Users\olika\PyCharmMiscProject\proxy_manadger_test

📌 СХЕМА ОБНОВЛЕНИЯ:

proxy_system (отдельный проект) парсит свежие прокси
Сохраняет в good_proxies.txt
loez_bot читает из этой же папки (через PROXY_DIR)
НИКАКОГО КОПИРОВАНИЯ ВРУЧНУЮ НЕ НУЖНО

📌 ФОРМАТ good_proxies.txt:
ip:port|дата время
Пример: 47.250.11.111:1081|2026-09-15 17:00:06

📌 ПРИОРИТЕТНЫЙ ПРОКСИ (из .env, текущий):
PRIORITY_PROXY=http://ЛОГИН:ПАРОЛЬ@IP:ПОРТ

Провайдер: Webshare.io
Тариф: ~$2.99/мес (100 прокси datacenter) или 1 прокси
Формат: http://ЛОГИН:ПАРОЛЬ@IP:ПОРТ
ВАЖНО: логин и пароль обязательны в URL!

Если работает — бот всегда через него
Если не работает — идёт по пингу из good_proxies.txt

📌 НАСТРОЙКИ ПИНГОВАНИЯ (в proxy_manager.py, обновлено 26.09):

PING_COUNT = 1 (1 пинг — быстро)
MAX_CONCURRENT = 200 (200 одновременных)
PING_TIMEOUT = 5 (5 секунд — чтобы приоритетный прокси успевал)
CACHE_TTL = 1200 (20 минут — кэш)
BAD_PROXY_TTL = 600 (10 минут — soft-blacklist)

📌 SOFT-BLACKLIST ПРОКСИ (новое, 26.09):

mark_proxy_bad() НЕ удаляет прокси навсегда, а помечает
на 10 минут (BAD_PROXY_TTL). Через 10 минут прокси снова
доступен. is_proxy_bad() проверяет статус.

Причина: если удалять навсегда, за пару часов можно сожрать
все прокси при частых сбоях.

📌 ДВОЙНАЯ ПРОВЕРКА ПРИОРИТЕТНОГО ПРОКСИ:

1-я попытка: обычный пинг (PING_TIMEOUT=5 сек)
2-я попытка (если 1-я провалилась): повтор с timeout=10 сек

Это защита от кратковременных лагов прокси.

📌 КЭШ ПИНГОВ:
data/system/proxy_pings_cache.json

📌 АЛГОРИТМ РАБОТЫ:

1. Загружает прокси из good_proxies.txt
2. Проверяет приоритетный (2 попытки)
3. Если приоритетный не работает — пингует ВСЕ прокси
4. Выбирает самый быстрый
5. При ошибке — переключается на следующий (soft-blacklist)

⛔ ВАЖНОЕ ПРАВИЛО (НЕ НАРУШАТЬ!):
НЕ МЕНЯТЬ СИСТЕМУ ПОДКЛЮЧЕНИЯ В main.py!
Используется только AiohttpSession(proxy=proxy_url).
Любые другие варианты (connector, ssl_context) — ЗАПРЕЩЕНЫ!

При одобрении заявки (approve_req_<id>):

1. Если у юзера БЫЛА старая роль:
   - Освобождаем её в roles_status.json
   - Инкрементируем changes_count
2. Занимаем новую роль
3. Обновляем/добавляем в users.json (обновление роли, not add)
4. В зависимости от должности:
   - Администратор (position="admin") → admins.json, ранг = 2
   - Модератор (position="moder") → admins.json, ранг = 3
   - Участник (position="member") → только users.json
5. Отправляем юзеру уведомление + ссылки:
   - CHAT_INVITE_LINK — всем
   - ADMIN_LINK — если rank 1, 2
   - MODERATOR_LINK — если rank 3

📌 Функции добавления:
add_user(user_id, username, full_name, role, extra, changes_count)
add_admin(user_id, username, full_name, rank)

📌 ЧТО ПРОИСХОДИТ:

   - Если changes_count >= max_role_changes → отказ
   - Владельцы (rank 1) не ограничены

   - Освободить старую роль A
   - Инкрементировать changes_count
   - Занять роль B
   - Обновить users.json

- Лимит общий (max_role_changes в настройках)

Все изменения фиксируются в CHANGELOG.md.

Актуальная версия: 7.4.0
Дата последнего обновления: 26.09.2026

[7.4.0] - Система смены роли:
- Новая настройка max_role_changes (по умолчанию 3)
- Поле changes_count в users.json
- Счётчик смен, лимит, предупреждение при подаче
- Освобождение старой роли при одобрении
- Команда /userstats + сброс счётчика админом

Баг-фиксы:
- Наложение ролей (было — две роли у одного юзера)
- Уведомления о заявках (admins.txt → admins.json)
- Подтверждение /free (Да/Нет)
- Ссылки после одобрения (CHAT_INVITE_LINK + ADMIN/MODERATOR_LINK)

Proxy Manager (переписан):
- PING_COUNT=1, PING_TIMEOUT=5
- Soft-blacklist прокси (BAD_PROXY_TTL=600)
- Двойная проверка приоритетного прокси
- Подключён Webshare.io

[7.3.0] - Зафиксированы версии библиотек
[7.2.0] - Порядок роутеров, unsubscribed_calls → .json, /message_all
[7.1.0] - JSON-формат, приоритетный прокси, FSM настроек
[7.0.0] - Переход на aiogram 3.x
[6.2.0] - Фикс role_utils
[6.1.0] - Правила удаления кода
[5.5.0] - Управление админами, настройки
[5.4.1] - Чистка кода
[5.4.0] - Напоминалка, /update
[5.3.0] - Система прокси с пингом
[5.2.0] - Бот-пересыльщик
[5.1.0] - Рефакторинг, Proxy Manager
[5.0.0] - Первоначальная структура
