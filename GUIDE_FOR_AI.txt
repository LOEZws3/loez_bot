📌 ОПИСАНИЕ ПРОЕКТА (ДЛЯ НОВОЙ ИИ)
═══════════════════════════════════════════════════════════════════

LoezF_Bot — Telegram-бот для управления приёмом новых участников (нью) 
во флуд-чаты и ролевые сообщества. 

⛔ ВАЖНО: Проект полностью завершён и стабильно работает.
⛔ НЕ ТРОГАТЬ СИСТЕМУ ПОДКЛЮЧЕНИЯ!
⛔ НЕ МЕНЯТЬ СТРУКТУРУ БЕЗ СОГЛАСОВАНИЯ!
⛔ ЛЮБЫЕ ИЗМЕНЕНИЯ ТОЛЬКО ПО СОГЛАСОВАНИЮ С ВЛАДЕЛЬЦЕМ!

🔹 ОСНОВНАЯ ЦЕЛЬ:
Автоматизация приёма новых участников (нью) во флуд-чаты.

🔹 АУДИТОРИЯ:
Участники фандомов и ролевых сообществ.

🔹 КЛЮЧЕВЫЕ ФУНКЦИИ:
✅ Приём нью через систему заявок
✅ Управление ролями и рестами
✅ Калы (созывы участников)
✅ Управление администраторами (ранги 1-3)
✅ Полная диагностика и настройки
✅ Поддержка прокси (автоматическое переключение)

🔹 ТЕХНОЛОГИИ:
🐍 Python 3.14
🤖 aiogram 3.17+ (установлено 3.29.0)
🗄️ SQLite (bot.db)
📁 JSON-файлы для данных

🔹 АРХИТЕКТУРА:
handlers/ — все обработчики команд
utils/ — вспомогательные функции
data/ — хранение данных
config.py — настройки
main.py — точка входа

🚨 ГЛАВНОЕ ПРАВИЛО: ВСЕГДА ЧИТАЙ RAW-ССЫЛКИ ИЗ GFA
═══════════════════════════════════════════════════════════════════

📌 ПО УМОЛЧАНИЮ — ЧИТАЙ ФАЙЛЫ ЧЕРЕЗ RAW-ССЫЛКИ ИЗ GFA!

1. Если AI НУЖНО прочитать файл (по ЛЮБОЙ причине, не только 
   по запросу "прочитай X.py") — он ОБЯЗАН использовать 
   Raw-ссылку из раздела "RAW-ССЫЛКИ" в конце GFA.
2. Если Raw-ссылка не работает — API-ссылка из дерева репозитория.
3. Только если оба не работают — web-ссылка github.com/.../blob/...
4. ЕСЛИ пользователь ЯВНО сказал "не читай" — можно отвечать без чтения.

📌 ЦЕЛЬ: экономия контекста чата + чтение актуального кода.

📌 ПРИМЕРЫ:
❌ НЕПРАВИЛЬНО: "Я предполагаю, что в файле X есть функция Y..."
✅ ПРАВИЛЬНО: [читает Raw-ссылку] → "В файле X я вижу функцию Y, она..."

⚠️ КРИТИЧЕСКИЕ ПРАВИЛА AIOGRAM 3.x
═══════════════════════════════════════════════════════════════════

❌ InlineKeyboardButton("текст", callback_data="...") — НЕ РАБОТАЕТ!
✅ InlineKeyboardButton(text="текст", callback_data="...") — правильно

❌ @router.message(F.text == "/apply") — не работает для команд!
✅ @router.message(Command("apply")) — правильно

❌ InlineKeyboardButton(callback_data="...") без text= — упадёт с ошибкой:
   "BaseModel.__init__() takes 1 positional argument but 2 were given"
✅ Всегда передавать text= именованным аргументом

📌 Причина: в aiogram 3.x InlineKeyboardButton — Pydantic BaseModel,
   который принимает ТОЛЬКО именованные аргументы.

📌 Примеры правильного кода:

    from aiogram.filters import Command
    from aiogram.types import InlineKeyboardButton, InlineKeyboardMarkup

    @router.message(Command("apply"))
    async def cmd_apply(message: types.Message):
        ...

    keyboard = InlineKeyboardMarkup(inline_keyboard=[
        [InlineKeyboardButton(text="✅ Одобрить", callback_data="approve_1")],
        [InlineKeyboardButton(text="❌ Отклонить", callback_data="reject_1")],
    ])

📝 ФОРМАТ requests.json (ТОЛЬКО СЛОВАРЬ!)
═══════════════════════════════════════════════════════════════════

📌 СТРУКТУРА (ВАЖНО!):

    {
      "1": {
        "user_id": 123456789,
        "username": "user",
        "full_name": "Иван Иванов",
        "role": "Ашра",
        "season": "Голос времени",
        "position": "moder",
        "position_name": "Модератор",
        "status": "pending",
        "created_at": "2026-09-13T17:00:00",
        "updated_at": "2026-09-13T17:00:00"
      },
      "2": { ... }
    }

📌 КЛЮЧЕВЫЕ МОМЕНТЫ:
- Ключ — ID заявки (строка)
- Значение — словарь с данными заявки
- status: "pending" | "approved" | "rejected" | "canceled"
- position: "admin" | "moder" | "member"
- position_name: "Администратор" | "Модератор" | "Участник"

⛔ НЕЛЬЗЯ использовать [] (список) — только {} (словарь)!
⛔ Пустой файл должен быть {} (2 байта), а не []

📌 ТИПИЧНАЯ ОШИБКА:
'list' object has no attribute 'items' — возникает, если файл содержит [].
Исправить: заменить содержимое на {}

📌 ВСЕ ПУТИ — АБСОЛЮТНЫЕ (через .resolve()):

    BASE_DIR = Path(__file__).parent.parent.resolve()
    SRC_PATH = Path(__file__).parent.resolve()
    DATA_DIR = str(BASE_DIR / 'data')

📌 ЛОГИ:
- Расположение: data/logs/bot.log
- Задаётся в config.py → LOG_FILE_PATH
- НЕ создавать log_dir = "logs" в main.py (устаревший подход)
- main.py импортирует LOG_FILE_PATH из config

📌 Причина: относительные пути зависят от рабочей директории
   (при запуске из PyCharm vs из start.bat — разные пути).

📌 Пример правильного логирования:

    from config import DATA_DIR, LOG_FILE_PATH, LOG_LEVEL, LOG_FORMAT, ensure_directories

    ensure_directories()

    logging.basicConfig(
        level=getattr(logging, LOG_LEVEL.upper(), logging.INFO),
        format=LOG_FORMAT,
        handlers=[
            logging.FileHandler(LOG_FILE_PATH, encoding='utf-8'),
            logging.StreamHandler(sys.stdout)
        ]
    )

При одобрении заявки (approve_req_<id>):
1. Роль становится "занята"
2. Пользователь добавляется в users.txt
3. В зависимости от должности:
   - Администратор (position="admin") → admins.txt, ранг = 2
   - Модератор (position="moder") → admins.txt, ранг = 3
   - Участник (position="member") → только users.txt (без admins.txt)

📌 Формат admins.txt: user_id|username|full_name|rank
📌 Формат users.txt: user_id|username|full_name|role|

📌 ОПИСАНИЕ:
Бот использует прокси для подключения к Telegram API.
Прокси загружаются из папки ../proxy_manadger/good_proxies.txt

📌 АЛГОРИТМ РАБОТЫ:
1. При запуске бот загружает все прокси из файла
2. Проверяет их работоспособность через Telegram API (пингование)
3. Выбирает самый быстрый рабочий прокси
4. Подключается через него
5. При ошибке (таймаут, соединение) — переключается на следующий по пингу
6. Если все прокси перепробованы — работает без прокси

📌 КЭШИРОВАНИЕ:
Результаты пингования сохраняются в proxy_pings_cache.json на 10 минут

⛔ ВАЖНОЕ ПРАВИЛО (НЕ НАРУШАТЬ!):
НЕ МЕНЯТЬ СИСТЕМУ ПОДКЛЮЧЕНИЯ В main.py!
Используется только AiohttpSession(proxy=proxy_url).
Любые другие варианты (connector, ssl_context) — ЗАПРЕЩЕНЫ!
Это проверено многократно — другие способы ломают бота!

🎯 РЕАЛЬНАЯ СТРУКТУРА roles_status.json
═══════════════════════════════════════════════════════════════════

📌 ФОРМАТ:

    {
      "Имя персонажа": {
        "status": "свободна" | "занята" | "ожидает" | "рест" | "бронь",

- Сезон лежит ВНУТРИ каждого персонажа.

cannot use 'dict' as a dict key — возникает, если role (из get_roles_by_season)
используется как строка. get_roles_by_season возвращает [{...}, ...],
нужно брать role.get('name') и role.get('status').
