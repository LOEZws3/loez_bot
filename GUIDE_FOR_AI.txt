📌 ОПИСАНИЕ ПРОЕКТА (ДЛЯ НОВОЙ ИИ)
═══════════════════════════════════════════════════════════════════

LoezF_Bot — Telegram-бот для управления приёмом новых участников (нью) 
во флуд-чаты и ролевые сообщества. 

⛔ ВАЖНО: Проект полностью завершён и стабильно работает.
⛔ НЕ ТРОГАТЬ СИСТЕМУ ПОДКЛЮЧЕНИЯ!
⛔ НЕ МЕНЯТЬ СТРУКТУРУ БЕЗ СОГЛАСОВАНИЯ!
⛔ ЛЮБЫЕ ИЗМЕНЕНИЯ ТОЛЬКО ПО СОГЛАСОВАНИЮ С ВЛАДЕЛЬЦЕМ!

🔹 ОСНОВНАЯ ЦЕЛЬ:
Автоматизация приёма новых участников (нью) во флуд-чаты.

🔹 АУДИТОРИЯ:
Участники фандомов и ролевых сообществ.

🔹 КЛЮЧЕВЫЕ ФУНКЦИИ:
✅ Приём нью через систему заявок
✅ Управление ролями и рестами
✅ Калы (созывы участников)
✅ Управление администраторами (ранги 1-3)
✅ Полная диагностика и настройки
✅ Поддержка прокси (автоматическое переключение)

🔹 ТЕХНОЛОГИИ:
🐍 Python 3.14
🤖 Aiogram 2.25.1
🗄️ SQLite (bot.db)
📁 JSON-файлы для данных

🔹 АРХИТЕКТУРА:
handlers/ — все обработчики команд
utils/ — вспомогательные функции
data/ — хранение данных
config.py — настройки
main.py — точка входа

═══════════════════════════════════════════════════════════════════
🔧 СИСТЕМА ПРОКСИ (НЕ ТРОГАТЬ!)
═══════════════════════════════════════════════════════════════════

📌 ОПИСАНИЕ:
Бот использует прокси для подключения к Telegram API.
Прокси загружаются из папки ../proxy_manadger/good_proxies.txt

📌 АЛГОРИТМ РАБОТЫ:
1. При запуске бот загружает все прокси из файла
2. Проверяет их работоспособность через Telegram API (пингование)
3. Выбирает самый быстрый рабочий прокси
4. Подключается через него
5. При ошибке (таймаут, соединение) — переключается на следующий по пингу
6. Если все прокси перепробованы — работает без прокси

📌 КЭШИРОВАНИЕ:
Результаты пингования сохраняются в proxy_pings_cache.json на 10 минут

⛔ ВАЖНОЕ ПРАВИЛО (НЕ НАРУШАТЬ!):
НЕ МЕНЯТЬ СИСТЕМУ ПОДКЛЮЧЕНИЯ В main.py!
Используется только AiohttpSession(proxy=proxy_url).
Любые другие варианты (connector, ssl_context) — ЗАПРЕЩЕНЫ!
Это проверено многократно — другие способы ломают бота!

═══════════════════════════════════════════════════════════════════
📢 НАПОМИНАЛКА ДЛЯ НЕЗАРЕГИСТРИРОВАННЫХ ПОЛЬЗОВАТЕЛЕЙ (НЕ УДАЛЯТЬ!)
═══════════════════════════════════════════════════════════════════

📌 ОПИСАНИЕ:
Когда пользователь пишет в чат, бот проверяет, есть ли он в базе.
Если нет — каждое 5-е сообщение напоминает о регистрации.

📌 АЛГОРИТМ:
1. При каждом сообщении в чате проверяется регистрация пользователя
2. Счётчик сообщений увеличивается для незарегистрированных
3. На каждом 5-м сообщении отправляется напоминание
4. Счётчик сбрасывается после напоминания

📌 ПРИВЕТСТВИЕ НОВЫХ:
Когда пользователь заходит в чат, бот отправляет приветствие с инструкцией.

📌 КОМАНДА /update:
Позволяет проверить статус регистрации и получить ссылку на бота.

⛔ НЕ УДАЛЯТЬ chat_member_router!
Без него напоминалка перестанет работать, а новые пользователи не будут получать приветствие.

🐛 ИЗВЕСТНЫЕ БАГИ И ИХ РЕШЕНИЯ
═══════════════════════════════════════════════════════════════════

1. Напоминалка не работает:
   → Проверить, что chat_member_router добавлен в __init__.py
   → Проверить, что функция check_user_registration обрабатывает сообщения в чате

2. Команды работают во флуде:
   → Добавлена проверка if message.chat.id == GENERAL_CHAT_ID
   → Проверить, что проверка добавлена во все команды

3. Кнопки не работают:
   → Проверить, что все обработчики зарегистрированы в __init__.py
   → Проверить, что текст кнопки точно совпадает с F.text
   → Добавлено логирование для отладки

4. Нет рабочих прокси:
   → Запустить proxy_checker.py для обновления списка
   → Или включить VPN и отключить USE_PROXY

5. Ошибка импорта из utils.role_utils:
   → В файл role_utils.py добавлены функции: get_seasons_list, get_roles_by_season, is_role_free, update_role_status
   → Эти функции используются новым интерфейсом /apply

🎯 РЕАЛЬНАЯ СТРУКТУРА roles_status.json
═══════════════════════════════════════════════════════════════════

📌 ФОРМАТ (ВАЖНО!):
{
  "Имя персонажа": {
    "status": "свободна" | "занята",
    "owner_id": null | <user_id>,
    "username": null | "<username>",
    "season": "Название сезона",
    "extra": ""
  },
  ...
}

📌 КЛЮЧЕВЫЕ МОМЕНТЫ:
- Это СЛОВАРЬ, а не список! Ключ — имя персонажа.
- Статусы на РУССКОМ: "свободна" / "занята"
- Сезон лежит ВНУТРИ каждого персонажа, не отдельно.
- Список сезонов получается через перебор всех персонажей.

📌 ТИПИЧНАЯ ОШИБКА:
`'str' object has no attribute 'get'` — возникает, если код ожидает список,
а получает словарь. Например: `for season_data in data: season_data.get('season')`
работает для списка, но НЕ для словаря. Для словаря нужно:
`for role_name, role_info in data.items(): role_info.get('season')`

🔘 REPLY-КНОПКИ vs INLINE-КНОПКИ
═══════════════════════════════════════════════════════════════════

📌 REPLY-КНОПКИ (внизу экрана):
- Отправляют текст как обычное сообщение
- Требуют обработчиков `@router.message(F.text == "текст кнопки")`
- Пример: "📋 Помощь (/help)" — при нажатии отправляется это сообщение
- Если обработчика нет — бот молча игнорирует

📌 INLINE-КНОПКИ (под сообщением):
- Отправляют callback_data
- Требуют обработчиков `@router.callback_query(F.data == "...")`
- Не отправляют текст в чат

📌 ВАЖНО:
Когда добавляешь новую Reply-кнопку в keyboards.py — 
ОБЯЗАТЕЛЬНО добавь обработчик `F.text == "..."` в тот же или другой файл!
